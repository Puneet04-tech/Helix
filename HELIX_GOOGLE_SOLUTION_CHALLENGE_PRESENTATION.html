  • c. Problem Statement: Hotels, hospitals, and public service platforms lose revenue and patient trust because digital systems fail silently. Existing tools like Datadog detect problems and send alerts — but stop there. A human must still manually diagnose and fix the issue, often at 3 AM, often taking hours. Brief about your solution

HELIX is a full-stack, multi-tenant SaaS platform that acts as an autonomous crisis intelligence layer for smart infrastructure. It monitors hotel and hospital applications in real time, detects anomalies using pre-trained AI models via HuggingFace, and autonomously responds to crises through a LangChain 4-agent pipeline and Playwright automation — all without human intervention.

The complete loop in under 60 seconds:
Event detected → In-memory pattern gate confirms threat → HuggingFace classifies anomaly → LangChain agents detect, analyse, respond, communicate → Playwright restarts service or blocks IP → WebSocket updates dashboard live → Role-personalized emails sent → Incident and PDF postmortem saved to MongoDB

Built with: NestJS, Next.js, MongoDB Atlas, LangChain JS, HuggingFace Inference API, Playwright, Socket.IO, Nodemailer. Deployed on Render (backend) and Netlify (frontend). Total infrastructure cost: $0 using free tiers.

Google AI Integration: Gemini API / Vertex AI used for natural language incident querying and anomaly classification — satisfies the Google Solution Challenge AI model requirement.

Opportunities

a. How different is it from existing ideas?

Datadog, PagerDuty, Sentry, and New Relic all detect problems and send alerts. A human still manually responds — often an hour later. HELIX closes the full autonomous loop: detect, analyse, act, document — with zero human involvement. No existing affordable tool does this. Additionally:

  • Built for non-technical operators (hotel managers, hospital administrators) — not DevOps engineers
  • Runs entirely on free cloud tiers — $0 infrastructure cost vs $15-30/server/month for Datadog
  • Multi-tenant SaaS with data isolation — one platform serves all clients securely
  • Features like Incident DNA Fingerprinting, Silent Canary, and Guest Impact Score exist nowhere else at any price point

b. How will it solve the problem?

When a hotel's booking system fails at 3 AM, HELIX detects the pattern within 5 seconds via the in-memory gate, classifies it as a service failure using HuggingFace, autonomously restarts the service via Playwright, sends role-appropriate emails (technical to developer, operational to manager, brief to owner), updates the public status page, and saves a complete postmortem PDF — all before a human would even see the first alert.

c. USP of the proposed solution

HELIX is the only monitoring platform that: (1) acts autonomously — not just alerts, (2) explains incidents in plain English to non-technical operators, (3) gets smarter after every incident through its self-healing knowledge base, (4) measures business impact in revenue terms not just uptime percentages, and (5) runs at zero infrastructure cost making enterprise-grade autonomous monitoring accessible to small hotels and hospitals in developing markets.

List of features offered by the solution

Core Features

  1. Real-Time Anomaly Detection — HuggingFace zero-shot classification via in-memory 3-strike gate. Fires only on confirmed real threats.
  2. Autonomous Crisis Response — LangChain 4-agent chain + Playwright restarts services, blocks IPs, enables maintenance mode automatically.
  3. Natural Language Incident Querying — Hotel managers ask plain English questions and get factual answers from real incident data via AI chatbot.
  4. Role-Based Crisis Communications — One incident triggers 3 simultaneous emails written differently for developer, manager, and owner.
  5. Automatic Postmortem PDF — LangChain generates a structured report + pdfkit exports as PDF after every resolved incident.
  6. Guest-Facing Auto Status Page — Public webpage auto-updated by HELIX. No staff needed. Shows uptime % and incident history.
  7. Multi-System Correlation — Groups incidents across services within 5 minutes and identifies shared root cause.
  8. Compliance Incident Logging — Full audit trail + one-click regulatory PDF export for HIPAA/PCI-DSS compliance.

Killer Differentiators (No Existing Tool Has These)

  1. Incident DNA Fingerprinting — Builds a unique pattern signature per incident. Matches new crises against past fingerprints before they fully form. System gets smarter monthly.
  2. Cascade Failure Simulation — Weekly micro-failure injection maps exactly which services cascade when any single service fails. Builds a Dependency Risk Map.
  3. Guest Impact Score — Translates every technical incident into real business numbers: guests affected, revenue at risk, bookings lost.
  4. Self-Healing Knowledge Base — Every resolution stored permanently. New incidents check this base first. Institutional memory that grows forever.
  5. Silent Canary System — Real end-to-end synthetic booking transaction runs every 10 minutes to verify system works from a guest's perspective.
  6. Incident Replay — Watch any incident unfold in real time on the dashboard with millisecond precision — like a flight black box for software.
  7. Cross-Client Anonymous Benchmarking — Clients see how their performance compares to anonymized peer organizations on the same platform.
  8. Emotional Tone Detection — Monitors incoming guest support messages for urgency and distress. Alerts front desk before situations escalate.

Process flow diagram

Write this as a numbered flow:

1. SDK installed in hotel/hospital app captures all HTTP events automatically
2. Events POSTed to HELIX backend (Render) via HTTP — SDK gets 200 response in under 10ms
3. NestJS writes event to MongoDB AND in-memory Map simultaneously
4. In-memory Map runs 3-strike check — are there 3+ same-type events in 5 minutes?
5. If NO: stop. If YES: check 60-second cooldown cache
6. HuggingFace Inference API called once — zero-shot classification of event batch
7. If score is "normal activity" above 0.7: stop. If anomaly confirmed: continue
8. LangChain fires 4-agent chain: Detection Agent → Analysis Agent → Response Agent → Comms Agent
9. Response Agent calls Playwright script as a LangChain tool — executes: restart / block IP / maintenance mode
10. Incident saved to MongoDB with full AI reasoning and actions taken
11. Socket.IO WebSocket emits incident to connected dashboard sessions in real time
12. Nodemailer sends 3 simultaneous role-personalized emails
13. Public status page updates automatically via MongoDB status field

Total time: under 60 seconds. Human involvement: zero.

Architecture diagram of the proposed solution

Draw or describe these 4 layers:

Input Layer:

Hotel App + SDK → Hospital App + SDK → Log Drain / Polling Agent

Processing Layer:

NestJS Backend (Render) → In-Memory Map (pattern gate, zero DB reads) → Bull Queue (for scale)

AI Brain Layer:

HuggingFace Inference API → LangChain 4 Agents → Playwright Scripts

Data Layer:

MongoDB Atlas M0 → Events Collection (TTL 30 days) → Incidents + Clients Collections

Key architecture principles:

  • Event-driven: no polling, zero wasted API calls
  • In-memory Map handles all hot analysis — MongoDB never read during detection
  • Multi-tenant: every document tagged with projectId — perfect data isolation
  • Free-tier compatible throughout
  • Deployed: Render (backend) + Netlify (frontend) + Atlas M0 (database)
